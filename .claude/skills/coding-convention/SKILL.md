# Coding Convention

Conventions for this Next.js + React + TypeScript + shadcn/ui (Tailwind CSS) project.

The full rules live in `.claude/rules/`. Read the file that matches the work at hand — there is no need to load all of them.

## Routing

| When working on                                                            | Read                          |
| -------------------------------------------------------------------------- | ----------------------------- |
| Components, props, handlers, file layout                                   | `.claude/rules/react.md`      |
| Styling, Tailwind, `cn()`, `cva`, `components/ui/*`, container, typography | `.claude/rules/shadcn-ui.md`  |
| Type declarations, event handler types                                     | `.claude/rules/typescript.md` |
| Naming variables, functions, booleans, state, types, components, files     | `.claude/rules/naming.md`     |
| Comments, `#region`, TODO/FIXME                                            | `.claude/rules/comments.md`   |

Reviewing code, or touching several of these at once: read all of them.

## Core rules

These apply to every `.ts`/`.tsx` file under `src/`. This is the short version — details and examples are in the files above.

- Components are **arrow functions** with `export default` at the **bottom** of the file. Exception: `components/ui/*` is generated by shadcn/ui and uses named exports — leave it alone.
- **Never destructure props in the parameter list.** Take `props`, destructure at the top level of the component.
- Props with `children` use the `FCC` type from `@/types/react`.
- Handlers inside a component are named `handleX`; handlers passed through props are named `onX`.
- **Never write a handler inline in JSX** — declare it above, reference it below.
- Arrow functions always have a `{ }` body. **No implicit returns** unless the return value is the point.
- Avoid `any`; declare types explicitly from the start. Event types come from `@/types/react`.
- Style with `className` (Tailwind). Use `cn()` from `@/lib/utils` for conditional classes or to allow overrides, and `cva` when there are several variants. No `style={{}}` unless the value is dynamic and cannot be a class.
- Import through the `@/` alias (`@/components/ui/button`), never a relative path.
- Use semantic HTML elements directly (`section`, `nav`, `main`...). No wrapper component like `Box`.
- Name things in **English**, after the domain, saying what they mean rather than what type they are. `camelCase` for variables and functions, `PascalCase` for components and types, `UPPER_SNAKE_CASE` for module-level constants, `kebab-case` for files and folders, except a file whose main export is a custom hook, which takes the hook's name (`queries/useAuth.ts`). Booleans are prefixed `is`/`has`/`can`/`should`; functions are verb + noun.
- Leave a blank line between blocks: imports, the component declaration, state, handlers, JSX.
- **The default is no comment.** Only comment what is genuinely hard to follow, and only say **why**.
- Comments are written in **English**.
- **No JSDoc** (`/** */`, `@param`, `@returns`) and no per-field comments on types — name things well instead.
- The main kind of comment is `#region`, in this order: `State` → `Queries` → `Derived` → `Handlers` → `Effects`. Never wrap the `return` JSX in a region. Use them as soon as the component has at least two non-empty groups.
